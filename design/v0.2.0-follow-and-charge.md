# 搜索机器人 v0.2.0 设计文档 —— 跟随模式修订与充电站重构

> 方案：状态机扩展 + 充电站内嵌实体（方案一）
> 定案日期：2026-07-10
> 依赖：v0.1.5 已完成功能

---

## 1. 问题陈述

当前版本（v0.1.5）存在以下体验问题：

1. **跟随模式下收集行为受玩家位置干扰**：机器人太近或太远玩家时，AI Goal 优先级冲突导致停止探索物资。
2. **交互/探测范围过小**：玩家观察到机器人需要靠得很近（如紧贴木桶）才能取物，`CollectItemsGoal.SEARCH_RADIUS = 16` 在实际运行中因路径或逻辑限制显得更小。
3. **充电站未与机器人产生实际交互**：充电站 BlockEntity 已存在（含能量槽与物品槽），但 `createMenu()` 返回 `null`，机器人无法真正使用它充电。
4. **出厂电量不符合设计**：v0.1.4 为修复"机器不工作"bug，在构造器硬编码初始电量为 `10000`。但定案要求"电池零件刚制作完成没电 → 组装后机器人也没电"。
5. **缺少低电量自动返航与没电保护**：机器人不会主动找充电站，没电后只是速度变慢，仍可执行收集等高耗能行为。

---

## 2. 总体方案

在 `SearchRobotEntity` 中引入显式状态机，将机器人生命周期划分为 4 个状态：

| 状态 | 标识 | 说明 |
|------|------|------|
| `WORKING` | 0 | 正常工作：跟随玩家，**移动途中并发收集**交互半径内的容器物品 |
| `RETURNING_TO_CHARGE` | 1 | 低电量（<20%）：中断工作，主动寻路到最近的充电站 |
| `CHARGING` | 2 | 正在充电：实体已从世界移除，完整 NBT 保存在充电站 BlockEntity 内 |
| `OUT_OF_POWER` | 3 | 完全没电：仅保留跟随行为，不收集、不探索，主动找玩家 |

充电站重构为**无 GUI、无限电量、单机器人舱位**：
- 机器人靠近后自动"进入"，实体被安全移除并序列化到 BlockEntity。
- 充电站渲染器检测到内部有机器人时，在站内渲染一个静置的机器人模型（半开放容器效果）。
- 充电速度极快（如 `+5000 FE/tick` 或瞬间充满），充满后立即在原地生成实体并恢复先前状态。

## 3. 详细设计

### 3.1 机器人状态机（SearchRobotEntity）

#### 新增/修改字段

```java
// 同步到客户端的状态标识
private static final EntityDataAccessor<Integer> DATA_ROBOT_STATE = 
    SynchedEntityData.defineId(SearchRobotEntity.class, EntityDataSerializers.INT);

// 目标充电站坐标（仅服务端使用，不需要同步给客户端，由状态推断）
private BlockPos targetChargingStation = null;

// 当前状态枚举
public enum RobotState {
    WORKING(0),
    RETURNING_TO_CHARGE(1),
    CHARGING(2),
    OUT_OF_POWER(3);
    
    final int id;
    RobotState(int id) { this.id = id; }
    static RobotState byId(int id) { return values()[id]; }
}
```

#### 状态转换规则

```
[任意状态] ──电量<20%且有充电站──> RETURNING_TO_CHARGE
[任意状态] ──电量=0──> OUT_OF_POWER
[RETURNING_TO_CHARGE] ──到达充电站并进入──> CHARGING
[CHARGING] ──充满电──> WORKING（恢复跟随状态）
[OUT_OF_POWER] ──电量>0（被玩家充电/其他方式）──> WORKING
```

#### tick() 逻辑调整

```java
@Override
public void tick() {
    super.tick();
    
    // 每 tick 根据能量更新状态（优先级从高到低）
    if (getEnergy() <= 0) {
        setRobotState(RobotState.OUT_OF_POWER);
    } else if (getRobotState() != RobotState.CHARGING 
               && getEnergy() < getMaxEnergy() * 0.2 
               && findNearestChargingStation() != null) {
        setRobotState(RobotState.RETURNING_TO_CHARGE);
        this.targetChargingStation = findNearestChargingStation();
    }
    
    // 原有移动耗能逻辑保持不变
    // ...
}
```

#### 初始电量修正

- 移除构造器中硬编码的 `setEnergy(10000)`。
- 实体生成时（`onAddedToWorld` 或从 NBT 加载时），若 NBT 中没有 `Energy` 标签（即新组装），则初始电量为 `0`。
- **例外**：从旧版本存档加载的机器人，若 NBT 中已有 `Energy`，则保留原值以确保兼容性。

### 3.2 AI Goal 调整

#### CollectItemsGoal（修改）

**目标**：跟随模式下，机器人**紧跟玩家**，在移动过程中**并发取物**。只要容器进入交互半径，立即尝试取物，不中断当前移动路径。取物完成后继续跟随，不会为了取物专门停下脚步或改变路线。

| 修改项 | 当前值 | 修改后 |
|--------|--------|--------|
| `INTERACTION_RADIUS` | `16` | `3`（交互半径，由感知部件等级决定，即机器人**不动**时能直接交互的最远距离） |
| `canUse()` 条件（跟随模式） | 受玩家距离限制 | **WORKING + 跟随模式下**：只要能量足够（>0）、背包未满，且周围 **交互半径** 内有容器，就尝试取物；**取物不阻塞移动**，机器人在跟随/移动途中"顺手"拿取 |
| 寻路到容器逻辑 | 到达容器后打开 GUI 取物 | **移除"专门为取物而寻路"的逻辑**。机器人始终优先跟随玩家，仅在**路过/靠近**容器时（距离 ≤ 交互半径）直接打开取物，取完立刻关闭 GUI 继续移动 |
| 可交互对象过滤 | 所有 IItemHandler | **仅方块容器**（箱子、木桶、熔炉等有 `IItemHandler` 的方块实体）。**排除**：其他机器人实体、玩家背包、掉落物实体 |

> **自检修正**：`canUse()` 不应在 `OUT_OF_POWER` 或 `RETURNING_TO_CHARGE` / `CHARGING` 状态下运行，以免低电量时继续耗能收集。

#### FollowOwnerGoal（修改）

- **跟随触发距离**从当前值调整为 **4~5 格**，停止距离保持 **1.5 格** 左右，确保玩家正常移动时机器人不会跟丢。
- 在 `OUT_OF_POWER` 状态下仍然运行，但速度倍率进一步降低（如从 `1.2` 降到 `0.6`），体现"没电缓慢跟随"。
- `OUT_OF_POWER` 时如果主人距离过远（> 16 格），尝试传送到主人附近（可选，避免机器人永远追不上飞行玩家）。

#### ReturnToChargeGoal（新增）

```java
public class ReturnToChargeGoal extends Goal {
    private final SearchRobotEntity robot;
    private BlockPos targetStation;
    
    @Override
    public boolean canUse() {
        return robot.getRobotState() == RobotState.RETURNING_TO_CHARGE
            && robot.targetChargingStation != null
            && robot.getEnergy() > 0; // 还有能量移动
    }
    
    @Override
    public void tick() {
        // 每 tick 向 targetStation 移动
        robot.getNavigation().moveTo(
            targetStation.getX() + 0.5,
            targetStation.getY(),
            targetStation.getZ() + 0.5,
            robot.getFollowSpeed() * 1.5 //  urgency multiplier
        );
    }
    
    @Override
    public void stop() {
        // 到达后尝试进入充电站
        if (robot.distanceToSqr(Vec3.atCenterOf(targetStation)) < 4.0) {
            BlockEntity be = robot.level().getBlockEntity(targetStation);
            if (be instanceof ChargingStationBlockEntity station) {
                if (station.insertRobot(robot)) {
                    robot.setRobotState(RobotState.CHARGING);
                }
            }
        }
    }
}
```

#### OutOfPowerGoal（新增，或合并到 FollowOwnerGoal）

为保持简洁，可将 `OUT_OF_POWER` 的行为直接并入 `FollowOwnerGoal`：
- `canUse()` 条件增加 `|| robot.getRobotState() == RobotState.OUT_OF_POWER`
- `tick()` 中若状态为 `OUT_OF_POWER`，跳过耗能代码，不触发收集。

### 3.3 充电站重构（ChargingStationBlockEntity）

#### 字段变更

```java
// 存储完整机器人 NBT（实体被移除后所有数据在此）
private CompoundTag storedRobot = new CompoundTag();
private boolean hasRobot = false;

// 充电速度：极快（每 tick 充 5000，或直接用 maxEnergy - currentEnergy 瞬间充满）
private static final int CHARGE_RATE = 5000;
```

> **自检修正**：`storedRobot` 必须包含足够的 NBT 数据以完整重建实体：
> - `stats` / `parts`（部件属性）
> - `Inventory`（背包物品）
> - `Energy`（当前电量）
> - `OwnerUUID`（主人）
> - `ExplorationMode`（模式）
> - `HomeStoragePos`（返航点）
> - `RobotState`（用于充满后恢复，应强制设为 `WORKING`）

#### 核心方法

```java
/**
 * 尝试将机器人存入充电站。
 * @return true 存入成功；false 站内已有机器人或失败。
 */
public boolean insertRobot(SearchRobotEntity robot) {
    if (hasRobot) return false;
    
    // 序列化机器人全部数据
    CompoundTag robotTag = new CompoundTag();
    robot.save(robotTag);
    
    // 记录状态用于充满后恢复
    robotTag.putString("PreChargeState", robot.getRobotState().name());
    
    this.storedRobot = robotTag;
    this.hasRobot = true;
    
    // 从世界移除实体
    robot.discard();
    
    setChanged();
    return true;
}

/**
 * 玩家手动将物品形态机器人放入充电站。
 * @return true 放入成功。
 */
public boolean insertRobotFromItem(ItemStack robotItem) {
    if (hasRobot) return false;
    
    CompoundTag robotTag = robotItem.getOrCreateTag();
    // 确保电量等数据存在
    if (!robotTag.contains("Energy")) {
        robotTag.putInt("Energy", 0);
    }
    
    this.storedRobot = robotTag;
    this.hasRobot = true;
    
    setChanged();
    return true;
}

/**
 * 将充满电的机器人释放回世界。
 */
public void ejectRobot() {
    if (!hasRobot) return;
    
    // 恢复电量到满（或 NBT 中的 maxEnergy）
    int maxEnergy = storedRobot.getCompound("stats").getInt("max_energy");
    storedRobot.putInt("Energy", maxEnergy);
    
    // 强制恢复为 WORKING 状态
    storedRobot.putInt("RobotState", RobotState.WORKING.id);
    
    // 在充电站上方生成实体
    SearchRobotEntity robot = new SearchRobotEntity(ModEntities.SEARCH_ROBOT.get(), level);
    robot.load(storedRobot);
    robot.setPos(worldPosition.getX() + 0.5, worldPosition.getY() + 1, worldPosition.getZ() + 0.5);
    
    level.addFreshEntity(robot);
    
    this.storedRobot = new CompoundTag();
    this.hasRobot = false;
    setChanged();
}
```

#### tick() 逻辑

```java
@Override
public void tick() {
    if (!hasRobot || level == null || level.isClientSide) return;
    
    int currentEnergy = storedRobot.getInt("Energy");
    int maxEnergy = storedRobot.getCompound("stats").getInt("max_energy");
    
    if (maxEnergy <= 0) {
        // 兼容旧数据：如果 stats 里没有 max_energy，回退到默认值 10000
        maxEnergy = 10000;
    }
    
    if (currentEnergy < maxEnergy) {
        // 极快充电：直接充满或每 tick 充大量
        storedRobot.putInt("Energy", Math.min(currentEnergy + CHARGE_RATE, maxEnergy));
        setChanged();
    } else {
        // 充满，自动释放
        ejectRobot();
    }
}
```

#### NBT 序列化

```java
@Override
protected void saveAdditional(CompoundTag tag) {
    super.saveAdditional(tag);
    tag.putBoolean("HasRobot", hasRobot);
    if (hasRobot) {
        tag.put("StoredRobot", storedRobot);
    }
}

@Override
public void load(CompoundTag tag) {
    super.load(tag);
    this.hasRobot = tag.getBoolean("HasRobot");
    if (hasRobot && tag.contains("StoredRobot")) {
        this.storedRobot = tag.getCompound("StoredRobot");
    }
}
```

#### 被破坏时的处理

```java
// 在 ChargingStationBlock 的 onRemove 或 playerWillDestroy 中调用
public void onStationDestroyed() {
    if (hasRobot && !level.isClientSide) {
        // 吐出机器人到地面上
        SearchRobotEntity robot = new SearchRobotEntity(ModEntities.SEARCH_ROBOT.get(), level);
        robot.load(storedRobot);
        robot.setPos(worldPosition.getX() + 0.5, worldPosition.getY() + 0.5, worldPosition.getZ() + 0.5);
        level.addFreshEntity(robot);
    }
}
```

#### 移除 GUI

- `ChargingStationBlock` 不再实现 `MenuProvider` 或返回 `new MenuProvider()`。
- `ChargingStationBlockEntity` 不再实现 `MenuProvider`；`createMenu()` 方法直接移除或返回 `null`。
- 右击充电站不再打开任何界面。

#### 玩家手动放入

`ChargingStationBlock.use()` 中增加以下逻辑：

```java
@Override
public InteractionResult use(BlockState state, Level level, BlockPos pos, 
                             Player player, InteractionHand hand, BlockHitResult hit) {
    if (level.isClientSide) return InteractionResult.SUCCESS;
    
    BlockEntity be = level.getBlockEntity(pos);
    if (!(be instanceof ChargingStationBlockEntity station)) return InteractionResult.PASS;
    
    ItemStack held = player.getItemInHand(hand);
    
    // 手持物品形态机器人 → 直接放入充电站
    if (held.getItem() instanceof RobotItem) {
        if (station.insertRobotFromItem(held)) {
            held.shrink(1); // 消耗一个物品
            return InteractionResult.CONSUME;
        }
        return InteractionResult.FAIL; // 站内已有机器人
    }
    
    // 空手右键且站内有机器人 → 取出（或等待自动释放）
    // 暂定：空手右键不做任何事，充满后机器人自动离开
    return InteractionResult.PASS;
}
```

> **注意**：若玩家推动实体机器人到充电站上，由 `ReturnToChargeGoal.stop()` 中的自动检测逻辑处理，无需额外代码。

### 3.4 充电站渲染（ChargingStationRenderer）

#### 新增文件

- `client/renderer/block/ChargingStationRenderer.java`

#### 逻辑

```java
public class ChargingStationRenderer implements BlockEntityRenderer<ChargingStationBlockEntity> {
    private final SearchRobotRenderer robotRenderer; // 复用机器人实体渲染器
    
    @Override
    public void render(ChargingStationBlockEntity station, float partialTick, 
                       PoseStack poseStack, MultiBufferSource buffer, 
                       int packedLight, int packedOverlay) {
        if (!station.hasRobot()) return;
        
        poseStack.pushPose();
        // 将机器人模型缩放到适合放在充电站内部的大小
        poseStack.translate(0.5, 0.3, 0.5);
        poseStack.scale(0.6f, 0.6f, 0.6f);
        
        // 渲染一个静态的机器人模型（可以不加动画）
        // 若需要更精细，可读取 storedRobot 中的部件数据渲染不同形态
        robotRenderer.renderDummy(poseStack, buffer, packedLight);
        
        poseStack.popPose();
    }
}
```

> **自检修正**：渲染时不需要真实实体，`SearchRobotRenderer` 需要提供一个 `renderDummy` 方法，或直接用 `EntityRenderer` 的通用方法渲染一个假实体。若过于复杂，v0.2.0 可先渲染一个与机器人模型相同的静态模型占位。

## 6. 测试策略

本项目以 Forge 1.20.1 运行时手动测试为主。v0.2.0 需要覆盖以下场景：

### 6.1 跟随与收集

- [ ] 新组装机器人初始电量为 `0`，放置后不会跟随也不会收集。
- [ ] 给电池充电后重新组装，机器人有电，放置后立即跟随玩家。
- [ ] 玩家行走、奔跑、跳跃时，机器人持续跟随，途中经过容器（箱子、木桶等）若在**交互半径（3格）**内会**顺手并发取物**，不中断跟随移动。
- [ ] 玩家与机器人距离拉远（> 32 格）时，机器人优先全力追赶玩家，不会因途中的容器停留或绕路。
- [ ] 机器人背包满后，停止收集。

### 6.2 低电量与充电

- [ ] 机器人电量降至 20% 以下时，自动中断收集，寻路到最近的充电站。
- [ ] 到达充电站后，机器人实体消失，站内可见机器人模型。
- [ ] 充满电后，机器人自动出现在充电站上方，恢复**跟随状态**，继续之前的工作。
- [ ] 若世界中**没有**充电站，电量低于 20% 后继续工作直到 0%。
- [ ] 电量为 0 后，机器人仅缓慢跟随玩家，不再收集容器。
- [ ] 电量为 0 时若玩家高速飞行远离，机器人尝试传送到玩家附近（若配置开启）。

### 6.3 充电站手动放入

- [ ] 玩家手持物品形态机器人，右键充电站，机器人被存入站内并开始充电。
- [ ] 站内已有机器人时，右键放入失败并给予提示（或粒子效果）。
- [ ] 充满电后，机器人自动出现在充电站上方，恢复之前的工作模式。

### 6.3 拆解与电量继承

- [ ] 组装台组装时，电池零件有 3000 电，组装出的机器人初始电量就是 3000。
- [ ] 机器人工作消耗至 1000 电后拆解，返还的电池零件电量为 1000。
- [ ] 新合成的电池零件电量为 0。

### 6.4 边界情况

- [ ] 充电站被破坏时，内部有机器人则吐出到地面，不丢失数据。
- [ ] 区块卸载时充电站正在充电，重新加载后充电继续，充满后正常释放。
- [ ] 服务器重启后，充电站内的机器人 NBT 完整保留。
- [ ] 从 v0.1.5 旧存档加载的机器人，若已有 `Energy` 字段，保留原值（兼容）。

## 7. 风险与回退方案

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| 实体存入/取出时出现坐标/世界引用错误 | 机器人消失或崩溃 | 使用 `level.addFreshEntity()` 和 `entity.discard()` 的标准组合；在 `ejectRobot()` 中校验 `level != null` 且非客户端 |
| 渲染器性能问题 | FPS 下降 | 充电站渲染器仅在 `hasRobot=true` 时执行；若机器人模型面数高，先用简化模型或仅渲染一个立方体占位 |
| 状态机与旧 Goal 系统冲突 | AI 行为异常 | 每个 Goal 的 `canUse()` 都显式检查 `RobotState`，确保状态互斥 |
| 电池零件没有独立类 | 电量 NBT 无处存放 | 若当前电池只是普通 `Item`，给 `ModItems` 注册时统一设置默认 NBT `energy=0`；或在 `RobotAssemblerBlockEntity` 中按物品类型判断 |

## 8. 待后续版本实现

以下功能在本设计中预留接口，但 v0.2.0 不实现：

- **探索模式与探索半径**：v0.2.0 仅实现跟随模式。探索模式（定位区域内自动巡逻、大范围搜索）及其探索半径将在后续版本开发。
- **感知部件等级影响交互半径**：当前硬编码 `INTERACTION_RADIUS = 3`，等部件属性系统完成后替换为感知部件等级相关公式。
- **充电站等级系统**：当前充电站无等级，无限电量。后续可重新引入等级，决定充电速度和能否存储能量缓冲。
- **多台机器人排队充电**：当前仅支持单机器人。后续可在充电站旁增设"等待区"逻辑。
- **游戏内白名单/黑名单设置**：当前硬编码只收取方块容器。后续在机器人 GUI 中新增一页过滤配置，让玩家设置白名单/黑名单（物品级别）。
