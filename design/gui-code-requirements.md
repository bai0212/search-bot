## R0（必做，纯 bug）电量条画错坐标系，压住玩家背包格子

**现象**：打开机器人仓库 GUI，电量和电量条压在玩家背包第一行格子上。

**根因**（已核对 1.20.1 反编译的 `AbstractContainerScreen#render`）：
`renderLabels(...)` 是在 `pose().translate(leftPos, topPos, 0)` 之后被调用的，
所以 **`renderLabels` 里的坐标已经是相对面板左上角**；原版自己就是
`graphics.drawString(font, title, titleLabelX, titleLabelY, ...)` 直接传相对坐标。

`RobotInventoryScreen#renderLabels` 里调的 `drawEnergyBar` 却又加了一次偏移：

```java
// src/main/java/com/cheng/search_bot/client/screen/RobotInventoryScreen.java:151
int barX = this.leftPos + 120;
int barY = this.topPos + this.inventoryLabelY;
```

`graphics.drawString(energyText, barX - 4 - width, barY, ...)` 和后面几个 `graphics.fill(...)` 同理。

**要求**：
1. `drawEnergyBar` 内**不要**再加 `this.leftPos / this.topPos`，直接用相对坐标。
2. 建议的相对坐标（原版风下面板是浅灰，条子放在「物品栏」标签同一行的右半段）：
   `barX = 112, barY = this.inventoryLabelY, barWidth = 52, barHeight = 6`；
   数字右对齐到 `barX - 4`。这条带子是 `BAG_TOP + rows*18 .. +14`（14px 高），
   6px 高的条子放得下，且离上下格子都 ≥4px。
3. 颜色用 `TechGuiTheme` 常量，别再写死 `0xFF...`（见 R3）。

**验收**：任意行数（1..10）下，电量条和数字都不与任何 `Slot` 的 18×18 区域相交。
可以在 `美术材质/GUI/风格库/原版风/mock_gui_vanilla.py` 里加一行断言先离线验，再进游戏看。

## R1（必做）机器人仓库：行数 ≥8 时贴图 blit 越界

**依据**（已核对代码）：
`RobotInventoryScreen.java:43` 是 `imageHeight = Math.max(116 + rows*18, 181)`，
`renderBg` 里 `graphics.blit(GUI_TEXTURE, leftPos, topPos, 0, 0, imageWidth, imageHeight)`。
行数 8 时 `imageHeight = 260`，而 `robot_inventory.png` 只有 256 高
（1.20.1 的 `GuiGraphics#blit(ResourceLocation,...)` 内部按 256×256 算 UV），
于是右侧过滤面板（烘到 `y=255`）会被采样到贴图外，出现重复/空白的条带。

**要求**（三选一，按改动量排序）：
1. blit 时把高度夹住：`Math.min(this.imageHeight, 256)`，面板下方多出来的部分由代码补底色 + 1px 黑边；
2. 或者把 `robot_inventory.png` 出成 256×320（要重出贴图，我这边跑脚本就行）；
3. 或者右侧面板也改成代码画（那就完全不吃贴图高度）。

过滤槽位坐标（`x=178/196`，`y=66..156`）和两个按钮（`x=178`，`y=18/40`，`76×18`）**不要动**，
贴图就是按这些坐标烘的。

### 2.2 「放入躯体才出现对应槽位」

- 判定条件：`SLOT_TORSO` 里有物品（躯干部件）。
- 内圈 10 格 + 外圈 6 格附件：没躯体时**不渲染也不可交互**。
  建议给这些 `Slot` 包一层 `isActive()`（`AbstractContainerScreen` 会跳过 `!slot.isActive()` 的槽位），
  同时在 `SlotItemHandler#mayPlace` 里也挡一下，避免鼠标残影/快捷键塞进去。
- 躯体槽、核心槽、输入/输出槽：始终显示（核心槽可以先亮着，让玩家知道要放核心）。
- 躯干等级决定可用数量（`design/parts-guide.md`：铜 3 / 铁 3.5 / 金 4 / 钻 6 / 下界合金 7 / 下界之星 10）：
  超出等级的轨道格子同样 `isActive()=false`，视觉上就是「电子壳层没填满」。

### 2.3 生效顺序（重要）

## R5（主体居中）三个界面的坐标差量

> 状态：R0 / R1 / R2 / R3 都已落地（装配台径向 + 背包分页栏都在代码里生效了，Screen 里也没有写死色值了）。
> 这一节是剩下的观感问题：**内容没有落在它所在区域的中心**。
> 目标效果对比图：`风格库/原版风/gui_mock_current.png`（现状）和 `gui_mock_centered_target.png`（改完）。
> 设计参照精妙背包（Sophisticated Backpacks）的做法：一个区域里的东西整体居中、
> 标题居中压在它管的格子正上方、面板不留单侧空白。画法仍然是原版风，不引入深色面板。

### 5.1 机器人背包 `RobotInventoryMenu` / `RobotInventoryScreen`

| 项目 | 现状 | 改为 | 理由 |
|------|------|------|------|
| 过滤槽 2 列 x | `178 + col*18` → 178,196 | `196 + col*18` → 196,214 | 右侧面板是 `174..256`（82px 宽），2 列只有 36px，现在贴左边缘，右边空 42px。居中后两侧各 21px |
| 过滤槽托盘框（贴图） | `176..215` | `194..233` | 跟着槽位走 |
| 「标记物品」标题 x | 固定 `178` | `215 - font.width(s)/2` | 面板中心是 215，标题要压在它管的格子上方 |
| 两个按钮 x | `178`，宽 76 | `177`，宽 76 | 76 宽在 82 里居中 → 左边界 177（现在 178..254，右边差 2px） |
| 分页栏 x | 从 `x=8` 往右排 | 整条在 `0..174` 里居中：`x = (174 - Σ宽 - 2*(n-1)) / 2` | 分页管的是左边这块储物区，就该居中在这块里 |
| 分页选中态底色 | `TechGuiTheme.ACCENT`（#404040，比面板深） | `BG_LIGHT`（#E0E0E0，比面板亮） | 原版所有页签都是「当前页提亮/抬起」，深色块在灰面板上读起来像被禁用 |

`quickMoveStack` 里过滤槽的索引顺序不用动，只改 `Slot` 构造里的 x。

### 5.2 装配台 `RobotAssemblerScreen`

| 项目 | 现状 | 改为 | 理由 |
|------|------|------|------|
| 「输入」标签 | `8, 60` | `8, 72` | 端口槽在 `(8,84)`，标签悬在 24px 上方，读起来不是一组；贴到槽上方 12px |
| 「输出」标签 | `222, 60` | `231, 72` | 端口槽在 `(230,84)`，标签要和槽左边缘对齐 |
| 拆解 / 组装 | `8,106` / `212,106` | **保持不动** | 已核对：两按钮中心分别在 26 和 230，关于 x=128 对称；往下挪会和外圈 `(91,142)`、`(147,142)` 两格重叠 |
| 躯干槽（原子核） | `(119,84)` | **保持不动** | 槽中心 128 = 面板中心，本来就居中 |

### 5.3 操控台 `RobotControllerScreen`

| 项目 | 现状 | 改为 | 理由 |
|------|------|------|------|
| `imageHeight` | 固定 `24 + 8*24 + 28 = 244` | `24 + 频道数*24 + 28` | 只有 1 个频道时下面空 7 行，界面一半是死的。行数变了贴图也得跟着变（见下） |
| 行内容 | 名称 8 / 模式 62 / 机器人 108,160 / 删除 224 | **保持不动** | 内容占 `8..236`，在 240 宽里左右各差 2px，肉眼看不出 |
| 「+」按钮 | `imageWidth/2 - 8` | 跟着新高度走：`24 + 频道数*24 + 4` | 底部工具条位置随高度变 |

贴图侧：`robot_controller.png` 现在是 8 行烘死的。`imageHeight` 改成动态后，
blit 高度要夹到 `Math.min(imageHeight, 244)`（和 R1 同一个写法），
超出贴图的部分由 `panelFrame` 兜边框；行分隔线本来就由代码画，所以贴图不用重出。

### 5.4 生效顺序

