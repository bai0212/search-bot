# 废案档 —— 爬行肢 + 爬墙功能

> **归档日期**：2026-10-28（v0.2.8 起移除）
> **移除原因**：爬行肢的「撞墙自动上爬」逻辑与重力来回拉扯，导致机器人移动时「上蹦瞎窜、到达后蹦来蹦去」。用户明确要求删除爬行肢和相关爬墙代码，改为追求稳定移动。
> **说明**：本文档保存被删除的全部代码，日后若想恢复，按文末「恢复方法」操作即可。

## 4. 跟随 AI 的爬墙逻辑（`FollowOwnerGoal.java`）

整个文件已简化为「飞行用 3D、步行用 2D」的单一距离逻辑。以下是被删除的爬墙相关部分：

删除的常量与字段：

```java
private static final float MIN_CLIMB_TRIGGER = 1.5f;

// 爬山期间的稳定目标方向（避免每次 recalc 改变方向导致脱墙）
private double climbTargetX, climbTargetZ;
private boolean hasClimbTarget = false;
```

删除的爬墙目标计算：

```java
/** 计算并保存爬墙时的稳定行走方向（只算一次，recalc 不改变） */
private void computeClimbTarget(LivingEntity owner) {
    double dx = owner.getX() - robot.getX();
    double dz = owner.getZ() - robot.getZ();
    if (Math.abs(dx) < 0.3 && Math.abs(dz) < 0.3) {
        // XZ 重合：用机器人面朝方向（之前 MoveControl 设的 yRot 指向墙）
        float yaw = robot.getYRot() * ((float) Math.PI / 180.0f);
        this.climbTargetX = robot.getX() - Math.sin(yaw) * 0.6;
        this.climbTargetZ = robot.getZ() + Math.cos(yaw) * 0.6;
    } else {
        // 朝主人 XZ 方向微移 0.6 格，确保撞墙
        this.climbTargetX = owner.getX() + Math.signum(dx) * 0.6;
        this.climbTargetZ = owner.getZ() + Math.signum(dz) * 0.6;
    }
}
```

删除的距离判断（原 `triggerDistSqr()` / `stopDistSqr()` 里的爬行肢分支）：

```java
// triggerDistSqr：
if (robot.canFly() || robot.hasCrawlingLimbs()) {
    return distSqr3D();
}

// stopDistSqr：
if (robot.hasCrawlingLimbs() && robot.onClimbable()) {
    return distSqr2D();  // 正在爬墙
}
if (robot.hasCrawlingLimbs()) {
    return distSqr3D();  // 有爬行肢还没上墙
}
```

删除的 `canUse()` 里的爬行肢特判：

```java
// 爬行肢 + 看不见主人：主人在墙/悬崖上方，XZ 相同但被墙隔开
// 此时实际 3D 距离仅 2-4 格，远小于 startDistance。跳过正常门槛。
if (robot.hasCrawlingLimbs() && !canSee) {
    float minTrigger = Math.min(startDistance, MIN_CLIMB_TRIGGER) + HYSTERESIS;
    if (distSqr3D() < (double) (minTrigger * minTrigger)) return false;
    this.owner = owner;
    return true;
}
```

删除的 `tick()` 里的爬行肢移动分支：

```java
} else if (robot.hasCrawlingLimbs()) {
    if (canSee) {
        hasClimbTarget = false;
        robot.getNavigation().moveTo(owner, currentSpeed);
    } else if (robot.onClimbable()) {
        // 正在爬墙中：不改变 MoveControl 方向，保持贴墙
        if (!hasClimbTarget) {
            computeClimbTarget(owner);
            hasClimbTarget = true;
        }
        robot.getMoveControl().setWantedPosition(
                climbTargetX, robot.getY(), climbTargetZ, currentSpeed);
        timeToRecalcPath = 8;
    } else {
        // 有爬行肢、未爬墙中：试着走到墙根
        boolean ok = robot.getNavigation().moveTo(owner, currentSpeed);
        if (!ok) {
            if (!hasClimbTarget) {
                computeClimbTarget(owner);
                hasClimbTarget = true;
            }
            robot.getMoveControl().setWantedPosition(
                    climbTargetX, robot.getY(), climbTargetZ, currentSpeed);
        }
        timeToRecalcPath = 5;
    }
}
```

## 7. 恢复方法

若要恢复爬行肢 + 爬墙功能：

1. **物品**：在 `ModItems.java` 重新加回 `CRAWLING_LIMBS` 注册和 `isPart` 的 `case "crawling_limbs"` 分支。
2. **属性**：在 `RobotStats.java` 的 `MOVEMENT_SPEED_BONUS` / `MOVEMENT_ENERGY_COST` 加回两条。
3. **实体**：在 `SearchRobotEntity.java` 加回 `isClimbing`/`climbTimer`/`CLIMB_PERSIST_TICKS`、`onClimbable()`、`hasCrawlingLimbs()`、`countCrawlingLimbs()`、`tick()` 爬墙状态块、`travel()` 上推代码、摔落减免。
4. **跟随**：`FollowOwnerGoal.java` 恢复爬墙分支（对照上面第 4 节）。
5. **装配器/标签/语言/资源**：按第 5、6 节补回。
6. 注意：恢复后需重新处理「稳定移动」问题——原爬墙逻辑是导致上蹦的主因，建议改为「仅当明确想爬墙时才上推」（例如只在跟随主人且主人在头顶高 2 格以上时），而不是「撞墙即爬」。

> 提示：`getOrDefent` 兜底让恢复时不必同时改装配器的统计循环。
